# Euronav5 Vector Database Format

Format used by the EuroNav planning station / A109 helicopter for user-drawn
vector overlays (lines, polygons, circles, zones). The iOS app must export
files in exactly this format.

**Every statement in these documents is verified byte-for-byte against the
reference data** in `Euronav5 avkodning/` (set1–set10, `full_db`,
`vector map data`). Anything that could not be proven is collected in
[VERIFICATION.md → Open questions](VERIFICATION.md#open-questions), not
sprinkled through the spec. Re-run the proof at any time:

```
cd "Euronav5 avkodning/analysis" && python3 verify_all.py
```

## What a card layer consists of

For each used layer `N` (1–6) the card carries four files under `db/SQL/`:

```
USERN.tbl      vector data    3480-byte header + pages of 4104 bytes
USERN-ID.idx   index          key = USEROBJECTID (figure id)
USERN-LN.idx   index          key = LONGITUDE (microdegrees)
USERN-OI.idx   index          key = ID (row number)
```

Everything is deterministic: the index files derive from the `.tbl`, and
the `.tbl` derives from the drawn figures plus genuine user inputs only
(timestamp, names, zone types, elevations, layer, draw order). The
USEROBJECTID numbering, style ids and warning flags follow fixed rules —
all 45 files of all 10 sets regenerate byte-exactly from figure-level
inputs (see [EXPORT_GUIDE.md](EXPORT_GUIDE.md#derived-rules-do-not-ask-the-user-for-these)).

## Historical note

The previous documentation (deleted `MD/` folder, `EURONAV5_FORMAT_COMPLETE.md`,
and the "DMG"/byte_08/byte_12/zone-block analyses) was based on a misreading
of the container: the "4297-byte template header" did not exist (real header
is 3480 bytes followed by 4104-byte pages), the "byte_08/byte_12 formulas"
were page-count and record bytes, "FigureCounter at 0xb0 BE" was the middle
of the DESCRIPTION column, and coordinates are not 6-bit encoded or
big-endian floats. None of the old byte formulas should be used.

The old `Euronav5ExportService.swift` implemented that incorrect model; it
was replaced (June 10, 2026) by `Services/Export/Euronav5Encoder.swift`
(byte-exact Swift port of `Euronav5 avkodning/analysis/euronav5.py`,
proven by `verify_swift.py`) with `Euronav5ExportService.swift` as a thin
adapter from the app's shape model.
